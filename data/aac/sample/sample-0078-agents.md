# Repository Guidelines

## Project Structure & Module Organization

- Core extension code lives in `src/extension.ts`; tests sit in `src/test/extension.test.ts`.
- Bundled output for VS Code loads from `dist/extension.js` (generated by webpack); transient build artifacts may appear in `out/`.
- Assets and icons reside in `images/`; configuration and metadata are defined in `package.json`, `tsconfig.json`, and `webpack.config.js`.

## Build, Test, and Development Commands

- `yarn compile` (webpack) builds the extension into `dist/`.
- `yarn watch` runs webpack in watch mode for iterative development.
- `yarn lint` runs ESLint on the TypeScript sources.
- `yarn test` executes the VS Code test runner (Mocha via `<REDACTED_USER>/test-electron`); `yarn watch-tests` recompiles tests on change.
- `yarn package` or `yarn vscode:prepublish` produces a production bundle (hidden source maps) suitable for publishing.

## Coding Style & Naming Conventions

- TypeScript project targeting ES2022 modules; keep imports sorted logically and prefer `const` over `let` when possible.
- Follow the existing two-space indentation and double-quoted strings shown in `src/extension.ts`; preserve trailing semicolons.
- ESLint rules (see `eslint.config.mjs`) warn on missing curly braces, loose equality, and import naming; run `yarn lint` before pushing.
- Use clear function and enum names (`createHtmlSnippet`, `SnippetFormat`) and keep helper logic small and pure.

## Testing Guidelines

- Tests use Mocha, Sinon, and the VS Code test harness; place new specs in `src/test/` and mirror the command behavior.
- Prefer focused unit tests for command flows (language detection, clipboard writes, configuration flags). Mock VS Code APIs as in the existing suite.
- Run `yarn test` before opening a PR; keep tests deterministic and avoid relying on the host editor state.

## Commit & Pull Request Guidelines

- Recent history follows concise, type-led messages (`feat: ...`, `chore: ...` with optional emojis). Use imperative mood and keep the subject under ~70 chars.
- For PRs, include: summary of behavior, key commands run (`yarn test`, `yarn lint`), and screenshots/gifs if UI output changes.
- Link to related issues if applicable and note any configuration defaults changed.

## Extension Configuration Tips

- User settings (via `package.json` contributes block): `copy-code-as-snippet.includeFilePath` (boolean, default `true`) and `copy-code-as-snippet.format` (`markdown|plain|html`, default `markdown`).
- When adding features, surface options through this config section and ensure defaults keep existing users unaffected.
